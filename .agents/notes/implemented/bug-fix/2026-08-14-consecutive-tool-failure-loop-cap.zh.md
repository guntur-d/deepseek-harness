# Agent Note: 限制连续全部出错的工具步骤

Status: implemented

[English](2026-08-14-consecutive-tool-failure-loop-cap.md) | 中文

## 问题

持续发出失败工具调用的模型会让 agent 步循环无界推进。观测到的触发场景：模型试图遵循注入的 AGENTS.md 指令（"read RULES.md"），却发出工具名为空的调用；每次都被执行为 `unknown tool ""`，错误被折叠回历史，模型又用另一个失败调用重试。该轮不断发起模型请求，直到操作者点击 stop——一个无界且昂贵的重试循环。

## 决策

agent loop 追踪工具调用全部出错的连续步骤，当超过 `maxConsecutiveToolFailures`（默认 3）时，以一条已记录且模型可见的通知结束本轮，而不是再发起一次请求。某一步若产出文本或至少提交一条成功的工具结果，则重置计数器。调度器报告每一步已提交的错误计数；loop 拥有本轮边界。计数与通知都是模型可见的，因此被记录（带 plugin 来源的 `user/message`），下一轮的历史会解释上一轮为何结束。

## 备选方案

**给失败调用更有效的错误信息。** 否决为唯一修复：模型仍可能重试，因此无论错误质量如何，loop 都需要硬性边界。

**在第一个退化（空名）调用时立即结束本轮。** 否决：合法并行调用中偶发的畸形调用不应丢弃合法调用，且单次失败可以恢复；边界应容忍少数连续失败。

**从 guard 插件终止。** 否决：`tools/post-execute` 只能接受或阻止单个调用；结束本轮是 loop 拥有的边界。

## 后果

全部步骤出错的轮现在会在配置的次数后以可见通知终止，从而限制成本与操作者等待时间。该上限是经过校验的 `agent-loop` 配置字段（正整数，默认 3），与 `maxParallelToolCalls` 一起暴露在 Settings 段。正常的逐步工具序列不受影响：任何带成功工具结果或纯文本的步骤都会重置计数器。
